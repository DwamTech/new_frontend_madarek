# طلب تعديل في الباكند: التعليقات وتفاعل الإعجاب/عدم الإعجاب

## السياق
كل صفحة مقال تعرض قسم تفاعل (`ArticleEngagement`) فيه عدّادا إعجاب/عدم إعجاب وقائمة تعليقات، مبني بالكامل في الواجهة الأمامية. القراءة (عرض العدّادين والتعليقات المعتمَدة) جاهزة تمامًا وتعمل تلقائيًا فور توفر النقطتين. أما **الإرسال** (تعليق جديد أو تصويت) فمعطَّل عمدًا في الواجهة حاليًا (أزرار وحقول disabled بعلامة "قريبًا") لأنه يحتاج قرارًا صريحًا منكم أولًا — انظر القسم الأخير.

## 1) القراءة — جاهزة للربط فورًا

**تعليقات مقال** — نقطة جديدة `GET /api/articles/{id}/comments`:
```json
[
  { "id": 5, "author_name": "أحمد", "text": "مقال ممتاز", "status": "approved", "created_at": "2026-09-01T10:00:00Z" }
]
```
- `status` إحدى: `"pending"` | `"approved"` | `"rejected"`. **الفلترة تحدث في الواجهة**: تُعرض `approved` فقط، دائمًا — لذا لا خطورة أمنية في إرجاع كل الحالات من هذه النقطة، لكن يُفضَّل أن ترجعوا `approved` فقط أصلًا لتقليل البيانات المنقولة.

**عدّادا الإعجاب/عدم الإعجاب** — نقطة جديدة `GET /api/articles/{id}/reactions`:
```json
{ "likes": 12, "dislikes": 1 }
```

الشكلان موثَّقان مسبقًا في الكود: [`RawComment`, `RawReactionCounts`](../../src/lib/mdarek-api/raw-types.ts) و[`Comment`, `ReactionCounts`](../../src/lib/mdarek-api/types.ts). حاليًا `getComments()`/`getReactionCounts()` تُرجعان قائمة فارغة/أصفارًا دفاعيًا (لا خطأ، القسم يظهر بلا بيانات).

## 2) الكتابة — يحتاج قرارًا مشتركًا قبل التنفيذ

إرسال تعليق جديد أو تصويت (إعجاب/عدم إعجاب) يحتاج نقطتي `POST` غير موجودتين، وهذا يتعارض مع قاعدة معمارية معتمَدة في الواجهة الأمامية: **قراءة فقط من `back.mdarek.net`، لا استدعاء لأي نقطة كتابة فيه** (انظر التعليق أعلى `src/lib/mdarek-api/index.ts`). لذا قبل تفعيل الإرسال نحتاج قرارًا منكم:

- هل تُضاف نقطتا `POST /api/articles/{id}/comments` و`POST /api/articles/{id}/reactions` إلى `back.mdarek.net` نفسه (مع مراجعة/اعتماد إداري للتعليق قبل ظهوره، بما يطابق حقل `status`)؟
- أم يُبنى مسار كتابة منفصل بالكامل عن النظام القديم (خدمة/جدول جديد) تستدعيه الواجهة الأمامية مباشرة؟

بمجرد تحديد المسار، تفعيل الأزرار في `ArticleEngagement` تعديل بسيط في الواجهة الأمامية فقط.

## لماذا لا نكتفي بحقول/آليات موجودة
لا توجد أي نقطة API حاليًا (قراءة أو كتابة) تخص التعليقات أو التصويت على المقالات في `back.mdarek.net` — هذه ميزة جديدة بالكامل.

## أثر التعديل على الموقع الحالي
- نقطتا القراءة الجديدتان: صفر أثر على أي صفحة أخرى، ولا تُعدَّلان أي استجابة قائمة.
- عدم تفعيل الكتابة الآن لا يكسر شيئًا — الأزرار تبقى `disabled` بوضوح للزائر ("قريبًا") بدل الاختفاء المفاجئ أو الفشل الصامت.
